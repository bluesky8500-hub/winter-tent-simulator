# 텐트 비교 위키 유지 규칙

이 디렉터리는 `catalog.sqlite`와 원본 자료에서 파생된 사람이 읽는 지식층이다. 구조화된 제품·가격·Claim·채택값의 Single Source of Truth는 계속 `db/catalog.sqlite`다.

## 세 층

1. 새로 첨부된 PDF와 사용자 제공 원본: 출처 자료. 공개 저장소에 PDF·엑셀·기존 HTML 원본을 넣지 않는다.
2. `db/catalog.sqlite`: 정규화된 Claim, 채택값, 출처, 충돌, 검증 상태의 기준.
3. `wiki/`: DB와 원본을 종합한 설명·비교·결정·질문을 연결한 Markdown 위키.

위키 문장은 DB를 대신하지 않는다. 계산에 쓰는 값이 바뀌어야 하면 DB에 새 Claim과 채택 이력을 먼저 기록한 뒤 관련 위키 페이지를 갱신한다.

## 상태 표기

- `확정`: 출처에 직접 적힌 사실이며 의미와 적용 대상이 명확하다.
- `채택`: 현재 계산이나 화면에 사용하는 값. 채택 근거와 조건을 함께 적는다.
- `충돌`: 둘 이상의 Claim이 양립하지 않거나 적용 범위가 불명확하다.
- `미확인`: 필요한 근거가 아직 없거나 이미지·문구가 모호하다.
- `계산`: 확정된 입력값으로 계산한 파생값. 계산식을 적고 직접 표기값과 구분한다.

## 새 자료 수집(ingest)

1. `index.md`와 관련 페이지를 먼저 검색해 같은 대상의 페이지가 있는지 확인한다.
2. 원본 파일은 수정하지 않는다. 출처 페이지에 공개 가능한 식별 정보, 자료 종류, 확인 날짜와 PDF 페이지를 기록한다. 이미지·긴 원문은 복제하지 않는다.
3. 새 사실이 기존 Claim과 같으면 출처를 추가한다.
4. 다르면 기존 값을 덮어쓰지 않고 `충돌` 또는 적용 조건이 다른 별도 Claim으로 남긴다.
5. 계산용 채택값은 자동 변경하지 않는다. 변경 사유와 사용자 확인이 있어야 한다.
6. 관련 제품·조합·쟁점 페이지와 `index.md`를 갱신한다.
7. `log.md`에 `## [YYYY-MM-DD] ingest | 제목` 형식으로 기록한다.

## 질문과 분석(query)

1. `index.md`에서 관련 페이지를 찾는다.
2. 위키의 현재 종합을 먼저 읽고, 필요한 경우 DB와 원본 페이지를 다시 확인한다.
3. 확정·채택·충돌·미확인·계산을 섞어 쓰지 않는다.
4. 유용한 새 비교나 결론은 기존 페이지에 통합하거나 새 페이지로 남긴다.
5. `log.md`에 `query` 항목을 추가한다.

## 상태 점검(lint)

- 깨진 링크와 고아 페이지
- 같은 대상을 다루는 중복 페이지
- 출처 없는 수치
- 채택값과 위키 설명의 불일치
- 해결되지 않은 충돌이 확정 사실처럼 쓰인 곳
- 검증이 끝났지만 `미확인`으로 남은 항목

`npm run wiki:lint`로 구조와 링크를 검사한다. 의미상의 충돌은 사람이 원본을 확인해야 한다.

## 작성 규칙

- 파일명은 영문 소문자 kebab-case를 사용한다.
- 내부 링크는 `[[products/coody-10-pro|쿠디 10.0 PRO]]`처럼 위키 루트 기준으로 쓴다.
- 모든 일반 페이지는 YAML frontmatter에 `type`, `status`, `updated`, `tags`를 둔다.
- 출처는 파일명과 PDF 페이지를 함께 쓴다. 마케팅 문구는 기술 사양으로 승격하지 않는다.
- 건조 난이도는 평가 항목에서 제외한다.
- 위키 Markdown은 검토 후 공개 GitHub 개발 저장소에 보존한다. 개인정보·비밀정보·로컬 절대경로·PDF 원문/이미지는 넣지 않는다. GitHub Pages에는 위키를 포함하지 않는다.
